# Software Foundry - Pi-Harness 软件工程母机技术架构规范

> **版本**: v1.0.0 (Architecture Baseline)  
> **核心范式**: Pi 双轨循环 (Dual-Loop) + 全插件化微内核 (Everything-is-a-Plugin) + 刚性视口 IDE 工作台 (GPUI)

---

## 一、 顶层设计哲学与双轨驱动模型 (Dual-Loop Architecture)

传统自动化工具容易陷入两个极端：死板生硬的 DAG 工作流（无法应对人类随时变更的主意），或者缺乏约束的纯 ReAct 乱撞（容易陷入死循环）。

Software Foundry 借鉴 **Pi 架构体系**，确立**“前台对话共识轨”与“后台自主执行轨”双轨异步并行、共享世界状态**的核心哲学：

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│                           Human User (自然白话/任何时刻可插话)                     │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│  Track 1: 对话与意图对齐循环 (Conversational Alignment Loop)                      │
│  - 倾听、业务澄清、共情、将口语诉求蒸馏为结构化业务规格 (Distilled Intent)        │
│  - 状态迁移: Listening -> Probing (主动追问) -> Synthesizing (共识规约成型)       │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │ 触发意图快照 (Intent Snapshot)
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│  Pi-Harness 微内核调度中枢 (Policy Dispatcher & Event Bus)                         │
│  - 维护工作区上下文树 (Workspace Context Tree) 与跨线程事件分发                   │
│  - 决策机制: Policy 动态仲裁 -> 激活对应技能/连接器 -> 触发安全护栏门禁 (HITL)  │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │ 派发后台任务信封 (Task Envelope)
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│  Track 2: 自主行动与工程自愈循环 (Autonomous Action & Self-Healing Loop)           │
│  - 纯后台异步无阻塞运行: 架构设计 -> 代码实现 -> 沙箱编译 -> 数据探活 -> 交付    │
│  - 状态迁移: Planning -> Action -> Observation -> Self-Healing (遇错反思) -> Done │
└───────────────────────────────────────────────────────────────────────────────────┘
```

## 二、 核心架构四大支柱

### 1. 分层三态记忆系统 (Tiered Memory Architecture)
为避免大模型上下文爆炸、注意力涣散与巨额 Token 消耗，废弃“无脑拼接全部历史聊天”的错误做法，确立严格的三态记忆隔离：

```
┌────────────────────────────────────────────────────────┐
│ 1. 工作记忆 (Working Memory): 当前轮次即时上下文       │
│    - 保留最近 3~5 轮有效问答，负责即时顺畅聊天          │
├────────────────────────────────────────────────────────┤
│ 2. 意图快照 (Intent Snapshot): 动态蒸馏的核心事实      │
│    - 包含: 系统命名、确认的业务模块清单、设计色系Token │
│    - 特点: 每次沟通后仅覆写最新结构化快照，恒定几百Token│
├────────────────────────────────────────────────────────┤
│ 3. 运行时状态记忆 (Runtime State Memory): 真实沙箱上下文│
│    - 包含: 当前源码指纹、最近一轮编译报错堆栈/Traceback│
│    - 特点: 仅在自愈循环时按需注入，自愈完成后即时归档  │
└────────────────────────────────────────────────────────┘
```

---

### 2. 沙箱驱动与工具调用协议 (Sandbox & Tool Invocation Protocol)
智能体绝不允许在宿主物理机上裸跑任何破坏性命令。所有执行必须通过统一的沙箱信封隔离：

*   **路径沙盒化 (Directory Isolation)**: 每个项目在初始化时被分配绝对隔离的专属工作区：`foundry_workspace/sandbox/{project_id}/`。
*   **环境变量动态注入**: 自动注入零依赖的 SQLite 测试数据模型：
    - `DATABASE_URL=sqlite:///app_data.db`
    - `SQLITE_DATABASE_PATH=...`
*   **结构化观测回传 (Observation Envelope)**: 捕获真实进程的 `exit_code`、`stdout`、`stderr` 与执行毫秒数。若 `exit_code != 0`，自动将 Traceback 注入自愈记忆中。

### 3. 一切皆是插件的契约化设计 (Everything-is-a-Plugin)
**微内核不包含任何具体的语言编译或第三方业务。微内核代码量低于 300 行，只负责事件分发与状态调度。大模型底座、角色技能、外部系统全部以平铺插件接入。**

```rust
#[async_trait]
pub trait FoundryPlugin: Send + Sync {
    fn id(&self) -> &'static str;
    fn name(&self) -> &'static str;
    fn kind(&self) -> PluginKind; // LLMProvider | Skill | Connector

    // 插件生命周期加载
    async fn on_load(&self, ctx: &mut PluginContext) -> Result<()>;

    // 暴露给母机的可用工具契约 (MCP Tools / Actions)
    fn get_tools(&self) -> Vec<AppToolDefinition>;

    // 统一工具执行中枢
    async fn call_tool(&self, name: &str, params: serde_json::Value) -> Result<serde_json::Value>;
}
```

*   **大模型网关插件 (LLM Provider)**:
    - `MagpiePlugin` (本地 `http://127.0.0.1:3425`，模型 `gemini-3.8-flash-high`)
    - `GeminiOfficialPlugin` / `DeepSeekPlugin`
*   **专职技能插件 (Agent Skills)**:
    - `RequirementsAnalystSkill` (需求分析与领域建模)
    - `DesignerSkill` (色系 Tokens 规约)
    - `CoderSkill` (全栈源码编写)
    - `QualityInspectorSkill` (沙箱语法与数据探活)
*   **外部连接器插件 (Connectors)**:
    - `GitHubConnector` (OAuth Device Flow / PAT 自动推分支提 PR)
    - `SqliteSandboxConnector` (自动初始数据建表与种子灌入)

### 4. 工业级隐性支柱 (Hidden Pillars for Industrial Robustness)

#### A. 状态快照与时光旅行回滚 (State Checkpointing & Time-Travel Rollback)
在每一轮执行潜在修改前，沙箱自动保存代码与数据库的状态 Checkpoint。
若 Agent 自愈循环在连续 2 轮内引入了更严重的语法错误，Policy 引擎自动触发 `rollback_checkpoint()`，恢复到上一个稳定版本并更换重试策略，杜绝代码被改烂。

#### B. 策略安全护栏与人机门禁 (HITL & Policy Guardrails)
*   无害操作（写临时文件、编译测试、代码阅读）：100% 自主静默执行；
*   破坏性/歧义操作（清空数据表、重大业务决策）：Policy 触发暂停门禁，向中栏前台发起结构化审批卡片（Human-in-the-Loop）。

#### C. 增量流式解析 (Incremental Streaming & Partial Render)
大模型生成时，采用 SSE 流式增量解析器。思维链（Chain of Thought）逐词打字机跳动，一旦识别到第一项业务模块或表名，界面立刻局部呈现，彻底告别“黑盒干等几十秒”的焦虑。

#### D. 任务预算与无限循环熔断 (Budgeting & Circuit Breaker)
*   最大迭代轮次: 5 轮；
*   单次命令超时: 30 秒刚性熔断；
*   超出预算自动中断并生成诊断报告，绝不允许无限死循环。

├────────────────────┬──────────────────────────────────────────┬────────────────────────────────────────┤

*   **线程隔离法则**:
    - **UI 主线程**: 耗时 0ms，纯非阻塞消费后台通道消息，保持 60fps 原生流畅，任何点击随时响应。
    - **后台工作线程 (Tokio Worker Pool)**: 处理大模型长思维链推导、沙箱执行与自愈，与前台无锁解耦。
